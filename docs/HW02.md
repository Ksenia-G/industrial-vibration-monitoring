# HW02. Прототип продукта.

**Краткое описание сути моего проекта:**

Продукт: браслет на запястье и дашборд для руководства (например, для бригадира или прораба). В дашборде собираются минуты работы с тяжёлым виброинструментом по каждому рабочему, и выскакивает уведомление, когда лимит выбран. 

В качестве "тяжёлого виброинструмента" взяла перфоратор Makita HR2470. У него лимит примерно 12 минут (для режима с ударом) на человека за смену (взято из паспорта). Бригадир видит уведомление, ставит этого рабочего на другую точку, инструмент берёт тот, у кого лимит ещё есть.

Смена считается эффективно отработанной, если работу доделали, и ни один человек не держал перфоратор дольше своих 12 минут. Получается, нет простоя благодаря такой ротации, а также, не превышается лимит работы на виброинструменте (что вызывает вибротравму, и из-за чего потом сотрудник вынужден уйти на больничный).


# 1. Гипотеза
**Если мы предлагаем:** 
- браслет рабочего + дашборд с аналитикой

**для:** 
- руководителя строительной бригады на объекте (бригадир, прораб)

**в сценарии:** 
- рабочие делят 1 перфоратор на несколько человек, бригадир наблюдает за распределением работ, 

**то мы получим:**
- 0 человек, работающих дольше 8-12 минут с тяжёлым виброинструментом в течение смены, и работа при этом доделана. 

**потому, что:** 
- бригадир видит, у кого лимит выбран, и отдаёт перфоратор тому, у кого он ещё есть. 

**Монетизация** 
- Браслеты и ПО разовая покупка, 
- Дальше только тех.поддержка, когда она нужна (условно, 5 часов в месяц).

# 2. Ключевые метрики
Ключевая метрика: число людей дольше 12 минут на перфораторе за смену. Цель 0. Измеряется по данным дашборда (суммарное время работы каждого сотрудника с перфоратором). Baseline — смена без дашборда, когда один работник использует свои 8–12 минут, после чего инструмент простаивает, а работа остаётся незавершённой. Частота измерения — один раз за смену.

Технические метрики: Macro-F1 — минимум 0,70 (цель 0,85); Recall класса «перфоратор» — цель 0,90. Обе метрики измеряются на отложенных записях, разделённых по сессиям. Baseline — первая обученная модель (возможно лог.рег). Частота измерения — при каждой новой версии модели.

# 3. Прототип
В прототип войдёт сам макет устройства на руке (микроконтроллер + акселерометр на макетной плате) + веб-интерфейс с аналитикой. 

На данном этапе не добавляю плату питания, также не делаю пайку, чтобы не усложнять прототип и не затягивать с началом испытания.

# 4. Компоненты
Из готового взяла микроконтроллер Esp32 и чип MPU-6050 c акселерометром. 
Самостоятельно выполняется: сбор и анализ данных, разметка, обучение моделей, архитектура приложения. Критично в данном случае, мне кажется собрать по несколько сессий с каждым инструментом.

# 5. Риск
Модель спутает перфоратор с другим инструментом (например с мощным шуруповёртом), тогда счётчик минут на дашборде не покажет реальные цифры. 

# 6. Критерии остановки 
- Эксперимент останавливается при успехе - если на отложенных записях macro-F1 не ниже 0,85.
- Также, эксперимент придётся остановить, если macro-F1 не получится выше 0,70 или перфоратор будет путаться с другим классом.
